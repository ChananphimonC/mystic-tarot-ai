# StarWhisper ✨🔮

A bilingual (Thai/English) AI tarot-reading web app. Ask a question, draw 3 cards
(Past / Present / Advice) with your mouse, touch, **or your bare hand via webcam
gesture control**, and get a reading generated by Gemini, grounded in each
card's real meaning. Also includes a daily fortune-cookie mini-feature.

Built primarily as a portfolio piece demonstrating prompt engineering,
lightweight RAG-style grounding, and computer-vision integration end to end —
see [`PRD.md`](./PRD.md) and [`PRODUCT.md`](./PRODUCT.md) for the full product
and architecture rationale.

## Features

- **3-card tarot reading** — pick a question or category (Love / Career /
  Finance / Health / General), draw 3 of 78 cards, get an AI-generated
  Past/Present/Advice interpretation plus a summary.
- **Daily Fortune Cookie** — crack a cookie for a random card + short
  AI-generated message, no caching, a fresh draw every time.
- **Hand-tracking card selection** — opt-in webcam gesture control: pinch your
  thumb and index finger to "click" anything on screen. Mouse and touch always
  work too; hand tracking is purely additive.
- **Bilingual UI** — Thai and English, switchable anywhere, including
  AI-generated reading text.
- **Original card art** — all 78 cards use procedurally generated SVG art
  (deterministic starfield + hand-authored glyphs), including a pip-count
  layout for number cards (e.g. Five of Pentacles visibly shows 5 coins).
  No copyrighted Rider-Waite-Smith artwork is used.
- **No accounts, no login, no usage quota** — fully client-stateless,
  Gemini's own rate limit is the only real limit.

## Tech Stack

| Layer | Stack |
|---|---|
| Frontend | React 19, TypeScript, Vite, Tailwind CSS v4, Framer Motion, Axios |
| Computer Vision | `@mediapipe/tasks-vision` (`HandLandmarker`), dynamically imported so it never bloats the main bundle |
| Backend | Python 3.11, FastAPI, Pydantic / pydantic-settings |
| AI | LangChain + `langchain-google-genai` → Google Gemini (`gemini-flash-lite-latest`) |
| CI | GitHub Actions (`.github/workflows/ci.yml`) — frontend lint/typecheck/build, backend install + import smoke test |

## Getting Started

### Prerequisites

- Node.js 20+
- Python 3.11+
- A [Google AI Studio](https://aistudio.google.com/apikey) API key (free tier works)

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env             # then edit .env and set GOOGLE_API_KEY
uvicorn app.main:app --reload --port 8010
```

### Frontend

```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

The Vite dev server proxies `/api/*` to `http://localhost:8010` (see
`frontend/vite.config.ts`), so the backend must run on port **8010** in
development — the frontend never talks to it directly, which sidesteps CORS
in dev entirely. The backend's `CORS_ORIGINS` setting only matters if you
serve the built frontend separately from the API in production.

## API Overview

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/cards` | List all 78 cards with their metadata |
| `POST` | `/api/shuffle` | Return all 78 card ids in random order (deck layout) |
| `GET` | `/api/daily-fortune` | Draw one random card + AI-generated fortune message |
| `POST` | `/api/predict` | Given a question, category, and 3 card ids → full AI reading |

Interactive docs: `http://localhost:8010/docs` once the backend is running.

## Concepts & Techniques Used

- **Prompt engineering** — persona prompting (`llm_service.py`'s "StarWhisper"
  system prompt) with an explicit grounding constraint ("don't invent
  symbolism that isn't listed").
- **RAG-lite grounding** — each card's real keyword meanings
  (`tarot_cards.py`) are injected straight into the prompt at request time,
  so the AI's output stays anchored to the actual card drawn instead of
  generic horoscope text. No vector database — the dataset is small and
  static enough that one isn't needed.
- **Structured output** — Pydantic schemas (`_StructuredReading`,
  `_DailyFortune`) force the LLM's response into typed fields via LangChain's
  `.with_structured_output(...)`, not just a hopeful "reply in JSON" prompt.
- **Computer vision** — MediaPipe `HandLandmarker` for real-time hand
  landmark detection, pinch-gesture recognition (thumb–index distance), and a
  **One Euro Filter** (adaptive low-pass filter) to smooth the cursor without
  introducing lag.
- **Clean architecture** — a strict frontend/backend split; all AI/LLM logic
  stays server-side in Python rather than leaking into client-side API routes.
